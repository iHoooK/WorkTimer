# Выпуск WorkTimer

## Сборка

Запустите `bash scripts/build.sh` на Windows x64. Версия, автор и ссылки заданы в `app/product.py`. Готовый установщик и папка portable находятся в `Build`. Комплект для публикации создаётся автоматически в `Release/Uploads`; рядом находятся HTML-гид, текстовая инструкция и готовое описание релиза. Не публикуйте рабочие каталоги, пользовательские базы, журналы или весь репозиторий вместо установщика.

Сборка формирует офлайн-руководство, юридические документы, историю изменений, перечень точных версий и полные лицензии. Библиотека pystray исключена из внутреннего архива и поставляется в `components` с исходниками и оригинальным архивом версии 0.19.5. При обновлении версии библиотеки добавьте соответствующий исходный архив в `licenses/sources`.

Условия собственного кода — MIT. Это разрешает пользователям в том числе распространять и продавать копии; репозиторий автора публиковать не требуется. Не обещайте полную юридическую защищённость: юридическая применимость условий зависит от обстоятельств и закона.

## Подпись EXE

Сертификат подписи кода удостоверяет издателя и позволяет проверить целостность EXE. Он не обязателен для запуска и не гарантирует отсутствие SmartScreen-предупреждений. Сейчас сертификата у автора нет: сборка остаётся неподписанной.

Когда сертификат появится, установите Microsoft SignTool и передайте параметры сборке: `--sign-thumbprint` (отпечаток сертификата из хранилища CurrentUser), `--timestamp-url` (HTTPS-сервер меток времени вашего центра), при необходимости `--signtool` (путь к signtool.exe). Используется SHA-256. Пароль и закрытый ключ в репозиторий не добавляются. Сборка подписывает и проверяет EXE программы, затем установщик; при неуспешной подписи выпуск останавливается.

## Проверка и публикация

- Проверьте `bash scripts/build.sh` и `scripts/smoke_installer.py`: запуск, сохранение, справку, лицензии, установку и удаление.
- После смены pystray проверьте загрузку совместимой изменённой библиотеки на готовом EXE.
- Проверьте адреса автора и платёжных платформ. Почты сейчас нет; приложение ссылается на сайт Promptix и обсуждения в «Кодовой Артели».
- Размещайте `WorkTimer-Setup-<версия>.exe` в публичном GitHub Release. Пользователю не нужны Python, Git и учётная запись GitHub.

## Встроенные обновления и GitHub Releases

Источник: `https://github.com/iHoooK/WorkTimer/releases`, задаётся в `app/product.py`. Для встроенных обновлений репозиторий и опубликованные релизы должны быть публичными. В программу не добавляются токены GitHub. Обычный push кода не является обновлением: нужен стабильный опубликованный Release с установщиком.

Версия задаётся в одном месте: `VERSION` в `app/product.py`, строго три числа `major.minor.patch`. Тег должен быть `v<версия>`, имя установщика — `WorkTimer-Setup-<версия>.exe`. Черновики, prerelease и версии ниже или равные установленной не предлагаются. SHA-256 берётся из метаданных файла GitHub либо из `SHA256SUMS` в том же релизе. Отсутствие установщика или контрольной суммы блокирует установку.

### Автоматическая сборка

1. Измените версию и историю изменений, сохраните изменения в Git и отправьте их в GitHub.
2. Создайте и отправьте тег, совпадающий с версией. Например, для первого выпуска с обновлениями:

```bash
git tag v1.0.2
git push origin v1.0.2
```

3. Workflow `.github/workflows/release.yml` проверит совпадение версии, соберёт Windows EXE, выполнит тесты и проверку установщика, затем создаст **черновик** релиза с установщиком, portable ZIP, `SHA256SUMS` и описанием из подготовленного шаблона. Если релиз этого тега уже создан вручную, его файлы сохраняются.
4. Проверьте черновик в GitHub → Releases, отредактируйте описание и нажмите Publish release. Релиз должен быть стабильным и помеченным Latest. После публикации установленная программа предложит обновление при следующей проверке.

GitHub Actions должен быть разрешён в репозитории; workflow использует штатный `GITHUB_TOKEN` с `contents: write`. Секреты пользователя в приложение не встраиваются. Подпись сертификатом пока не настроена в CI; локальную подписанную сборку публикуйте вручную после подготовки контрольных сумм.

### Ручной выпуск

```bash
bash scripts/build.sh
.packaging-venv/Scripts/python.exe scripts/smoke_installer.py
.packaging-venv/Scripts/python.exe scripts/github_release.py
```

Полная сборка уже запускает подготовку комплекта автоматически; последняя команда позволяет повторить этот шаг отдельно, ничего не публикуя. В `Release/Uploads` появятся установщик, `WorkTimer-Portable-<версия>.zip` и `SHA256SUMS`. В `Release` находятся `GUIDE.html`, `GUIDE.md` и `RELEASE_NOTES.md`. Прикрепите именно три файла текущей версии к стабильному GitHub Release с тегом `v<версия>` и опубликуйте его. Каталог `Build` по-прежнему содержит только установщик и готовую папку portable. Пересчитайте суммы после любой переподписи установщика.

### Первый переход и ограничения

Выпуски до 1.0.2 не содержат механизма обновления. Пользователям нужно один раз вручную поставить 1.0.2 или новее поверх прежней программы. `AppId` установщика постоянный: история и настройки в `%LOCALAPPDATA%\WorkTimer` сохраняются.

Кнопка установки работает для зарегистрированной установки текущего пользователя Windows и только если путь запущенного EXE совпадает с реестром. Portable и исходники показывают ссылку на релизы. При обновлении пользователь подтверждает скачивание; сессия сохраняется на паузе, база копируется до замены файлов, установщик ждёт завершения процесса и запускает приложение с прежними портом и каталогом данных. Закройте другие профили, использующие ту же установленную программу, перед обновлением.

SHA-256 и HTTPS защищают от повреждения загрузки и подмены вне доверенного GitHub-источника. Они не заменяют Authenticode и не защищают от захвата учётной записи издателя. Запросы не содержат пользовательских задач или истории. До публикации публичного релиза ожидаемо сообщение «Публичных релизов пока нет или репозиторий ещё закрыт».

Документация протокола: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release), [параметры установщика Inno Setup](https://jrsoftware.org/ishelp/topic_setupcmdline.htm).

## Пошаговая публикация через браузер

Для первого ручного выпуска используйте [полный гид](GITHUB_RELEASE_GUIDE.md). Готовые файлы для загрузки — в `Release/Uploads`, описание — в `Release/RELEASE_NOTES.md`. Загружайте два варианта программы и файл контрольных сумм в Assets релиза. HTML-гид остаётся на вашем компьютере.

Исходный шаблон гида — `docs/GITHUB_RELEASE_GUIDE_TEMPLATE.md`; актуальный гид создаётся подготовкой релиза. Описание собирается из `docs/RELEASE_NOTES_TEMPLATE.md` и раздела текущей версии в `docs/CHANGELOG.md`.
